# Product Requirements Document (PRD)

## 1. Product overview

**Product name:** Metro Mumbai — Smart Metro Guide  
**Platform:** Android mobile application  
**Product category:** Public-transport information and metro journey planning  
**Primary purpose:** Help passengers plan journeys using verified Mumbai Metro station and corridor data.

The app is inspired by the convenience of commuter-information apps such as m-Indicator, but it is an original product focused only on Mumbai Metro. It must not copy another product's branding, logo, proprietary content or exact screen design.

## 2. Problem statement

Passengers need a simple way to:
- Find a route between two Mumbai Metro stations.
- Understand which metro line to board and where to interchange.
- Compare valid route options.
- View station and corridor information.
- Access saved journeys and station favourites.
- See service notices when reliable information is available.

## 3. Goals

1. Deliver a usable Android app with a reliable station search and route planner.
2. Demonstrate advanced data structures and algorithms through a real route engine.
3. Show an interactive map with verified station and corridor information.
4. Work offline for core route planning after the local dataset is installed.
5. Clearly communicate the freshness and reliability of data.
6. Produce a buildable Android Studio project and APK.

## 4. Non-goals for the first release

- Mumbai local trains, BEST buses, taxis, autos or other cities.
- Ticket booking, QR ticket generation or payment processing.
- Guaranteed real-time train arrival or live crowd information.
- Turn-by-turn indoor navigation inside stations.
- User accounts, social features or chat.
- Unverified fare estimation.
- A claim that the app is official or operator-affiliated.

## 5. Target users

### Primary: Daily commuter
Needs a quick route, interchange instructions and saved journeys.

### Secondary: Occasional traveller
Needs station search, line information, map and simple journey steps.

### Tertiary: Student/evaluator
Needs a clear demonstration of graph modelling, BFS, Dijkstra, priority queue, hash maps and route reconstruction.

## 6. MVP feature requirements

### FR-01 Home
- Show app name and source/destination station selectors.
- Provide swap and search actions.
- Show recent and favourite journeys.
- Provide shortcuts to map, routes and alerts.
- Show data freshness or a notice if live status is unavailable.

### FR-02 Station search
- Search station names case-insensitively.
- Show line colour and interchange badge where verified.
- Support keyboard input and clear action.
- Prevent source and destination from being the same.
- Handle empty and no-result states.

### FR-03 Route planning
- Find valid routes from the local station graph.
- Provide minimum-stop route using BFS.
- Provide minimum-weight route using Dijkstra when verified edge weights exist.
- Show station sequence, line sequence, transfers and interchange names.
- Show alternatives only when they are valid and meaningfully different.
- Reconstruct the route using predecessor/parent data.
- Explain when no route exists in the currently loaded network.

### FR-04 Journey details
- Show boarding station, intermediate stations, interchange points and destination.
- Identify line changes clearly.
- Show number of stops and interchanges.
- Show travel-time estimate only if supported by verified edge-time data.
- Show fare only if a verified line-specific fare source is available.

### FR-05 Metro map
- Show Mumbai Metro station and corridor information on a map or schematic map.
- Distinguish metro lines by official line colours where verified.
- Allow station selection and opening station details.
- Support map zoom and pan.
- Do not invent station coordinates or connections.
- Clearly distinguish geographic map markers from schematic route lines.

### FR-06 Station details
- Station name, corridor/line, verified interchange information.
- Previous and next stations where route order is known.
- Verified facilities only.
- Actions to set as source or destination.

### FR-07 Saved and history
- Save and remove favourite stations and routes.
- Keep recent searches locally.
- Allow users to clear their history.
- No sign-in required for MVP.

### FR-08 Service alerts
- Display only alerts from a connected, reliable source or manually maintained verified dataset.
- Include source and timestamp.
- Label sample content as DEMO.
- If no live source exists, display “Live service status unavailable”.

### FR-09 Settings and information
- Theme preference.
- Data sources and last updated dates.
- About, privacy and feedback screens.
- Independent-app disclaimer.

## 7. Non-functional requirements

- Android phone layouts, including small and large screens.
- Core station search and route planning must work offline.
- Route calculations must not block the UI thread.
- Use accessible contrast, readable typography and touch targets.
- App must handle missing network, empty data and invalid inputs gracefully.
- No secrets or API keys committed to source control.
- Unit tests for algorithms and route edge cases.
- Clear separation between verified data and demo data.

## 8. Geographic and corridor scope

Initial dataset may start with these corridors, subject to official verification:
- Metro Line 1: Versova–Andheri–Ghatkopar.
- Metro Line 2A: Dahisar East–D.N. Nagar.
- Metro Line 7: Dahisar East–Gundavali.

Do not assume all proposed, under-construction or partially operational corridors are active. Add more corridors only after verifying station sequence, operational status and interchange links from official sources.

## 9. User journeys

### Journey A: Find a route
Home → choose source → choose destination → Search → view recommended route → open journey details.

### Journey B: Explore a station
Home/Map → tap or search station → station details → set as source or destination.

### Journey C: Save a route
Route results → tap Save → route appears in Saved → reopen later.

### Journey D: Check service information
Home → Service Alerts → read source and last-updated time; if no feed is connected, see unavailable state.

## 10. Success criteria

- User can search a station from the approved dataset.
- User can find a valid route between connected stations.
- BFS and Dijkstra return expected results on test graphs.
- Interchanges are identified correctly.
- Route detail matches the computed path.
- Core route planning works with airplane mode enabled.
- Map markers correspond to verified station coordinates.
- Missing live/fare data is not fabricated.
- APK builds successfully in Android Studio.

## 11. MVP acceptance criteria

A feature is accepted only when:
1. It works on a real Android device or emulator.
2. Empty, loading, success and error states are handled.
3. Data shown is traceable or explicitly labelled demo.
4. Tests cover the key logic.
5. It is connected to app navigation.
6. It does not contain non-functional placeholder controls.

## 12. Risks and assumptions

- Official datasets may be spread across multiple operator and government sources.
- Some corridors may have changed operational status; verify close to release.
- Official fare rules may differ by line/operator and may change.
- Google Maps SDK displays a map but does not itself provide authoritative metro routing or fare data.
- Google Maps API key and billing configuration may be required depending on APIs and usage.
- AI-generated code requires review, build validation and testing.
